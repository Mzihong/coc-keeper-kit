## 问题

Keeper 手上有一份阿卡姆城市资料(`reference/阿卡姆.docx`,当前未入库),原始诉求是
**做成地点模板**。直接做成模板是错的,两条理由:

1. **撞铁律。** 阿卡姆是虚构内容 + 具名角色绑定商业产品,按 `core/00-how-to-run.md`
   ground rules 的三分法属 ②③;2026-08-03 的转载放宽**只覆盖规则内容**。它最多能进
   `reference/sourcebooks/`(第三方归档、带引用出处、不进 bundle),**不能成为
   `campaigns/` 直接抄的模板**——"进 campaigns 的内容仍然自己写"这条没被放宽。
2. **撞一个已经下过的设计决定。** `core/01-intake.md`(era & place 的 auto-fill 行)
   与 `reference/tables/locations.md` 开头都在**主动对抗**「默认新英格兰小镇」的引力
   ——中文战役放新英格兰,每个 NPC 名字都变成翻译问题。一份开箱即用的阿卡姆会把这条
   引力从"模型的默认倾向"升级成"仓库里有现成文件的最省力路径",`locations.md` 那张
   d20 表当场作废。

**资料真正的价值在体例不在内容**:一个 1920s 新英格兰城镇由哪些部件组成——机构清单、
社会分层、交通与经济、一个地点条目该写哪几个字段、秘密怎么分三层埋。这是**手法**,
`reference/craft/` 就是为它准备的目录。

## 勘察结果(2026-08-04)

### §0 为什么不切分

`sourcebooks/keeper-rulebook-7e-zh.md` 17,469 行只能靠 grep 定位,是因为它**没有可预测
的标题体系**。本文档相反,自带索引:

- 只有 4 个 L1(前言 / 欢迎来到阿卡姆 / 阿卡姆历史 / 阿卡姆指南),第 4 个占了全书 82%
- 名录条目一律 `## <编号>`,**首位数字即区号**(1xx–9xx 城内、10xx 郊区),
  `sed -n 'a,bp'` 按行号跳读精确又便宜
- 文末自带一张按分类反查的总索引(见 §4)

切分只会在 gitignore 目录外多一份副本,换不到导航收益。**替代动作是下面这张行号表**,
后续会话照它跳读,不要重新 grep 全文。

### §2 地点条目的字段体例

```
## <三位或四位编码>        ← 首位 = 区号,后两位 = 区内序号;非按街道排序
### <地点名>
<街道地址,门牌号斜体>
<散文描述:功能 / 营业时间 / 租金或价格等硬数字 / 一条钩子>
#### <住客或雇员姓名>       ← 可选,人物子条目
**重要技能**:<技能名 数值>  ← 可选,只给与该地点有关的技能
```

样本:114(纯设施,4 行)、116(公寓 + 一个房客子条目 + 重要技能)、
103(纯人物条目,一整段行为模式 + 一个神话钩子)。
**观察到的三档密度**:一句话设施 / 一段带钩子的场所 / 带 NPC 子条目的场所——
同一张名录里混排,不强求每条等长。这本身是可提炼的手法。

### §3 门牌编号法则(§二 最值钱的一块)

第 934–947 行的 `### 寻找地址` 一节**与阿卡姆完全解耦**,抽象出来任何镇都能用:

- 编号原点定在两条主街的交汇处,四个方向各自从 100 起升序
- 大街区(横跨多个路口的)按四个街区计数
- 沿升序方向行进,**偶数在右、奇数在左**
- 只出现在城镇四分之一区域的街道不带东/西/南/北前缀
- 街道拐弯、加建、院内巷内地址会让编号出错——**这是特性不是 bug**
- 小巷一律不上图,明说留给 KP 现场发挥

## 拍板结果(2026-08-04,三条全部定案)

### 1. 全文不归档 —— 这条不是取舍,是硬约定已经答了

原以为"收进 `reference/sourcebooks/` 带引用出处"是个可选项。核过之后不是:

- `core/00-how-to-run.md`「Citing official material」第 2 条写死,2026-08-03 的转载放宽
  **只覆盖规则内容**;已出版的*虚构*内容(小说、模组正文、商业战役里的具名角色)
  仍归旧的严格规则——**取手法,永不取文字**
- `reference/sourcebooks/README.md` 自我定义是"给生成器当**数值标尺和原文核查**用",
  现有三份(规则书 / 魔法大典 / 怪物之锤)**全是规则内容**,收阿卡姆会开第一个口子
- 别拿 `craft/lovecraft-zh.md` 当先例——它能把 82 篇原文放进 `reference/og_Norval/`,
  是因为**洛夫克拉夫特是公版**。阿卡姆是 Chaosium 的商业设定书,不是同一回事

**结论:不归档 —— 这条拍板 2026-08-04 晚复核后维持,一个字没改。** 上面三条理由针对的是
「要不要收进 `reference/sourcebooks/`」:不走 `core/14` 流程、不当引用来源、不进反向索引、
提炼稿仍然是唯一入库产物。附带好处:reindex 的 orphaned 风险不存在,收尾第一条可以划掉。

> **⚠️ 同日晚有一处**改了**,别把两件事混成一件:`_source/arkham-zh.md` 与
> `arkham-maps/` **现在入版本库了**(`.gitignore` 不再整目录忽略 `_source/`,只挡
> `.pdf`/`.docx` 原件)。
>

### 2. 文字地图卡 —— 3 张,全部原创小镇;规范"记法",不规范内容

**同一条「取手法不取文字」也管这里**:照阿卡姆北区的真实街道写一张卡,等于把设定内容
换个格式复现。所以卡上的镇一律**原创**,arkham-maps 的 20 张图只作**记法**的参照物。

Keeper 提的约束是「想规范化流程,但不想定太死,每次开团地图要有多样性」。
**多样性不由地图卡提供**——它由掷骰提供(`locations.md` + 下面第 3 条的
`town-institutions.md`)。骰子决定这镇有什么,卡只决定怎么写下来。据此三条挡法:

- **样例不做成"一个能直接用的镇"**,只演示记法(同 `lovecraft-zh.md` 给技法字典
  而非小说选段)
- **字段分必填与选填,必填只剩两项:区名、相邻关系。** 「每区 3–5 个地点」降级成
  **建议区间**,并明写:区数与地点数随镇的规模走,**2 区的矿村与 9 区的城都合法**
- **镇级样例做两张形状迥异的镇**(4 区海港 / 2 区内陆矿村)。一张样例天然会被当模板抄;
  两张对不上的样例,示范出来的只剩"格式装得下不同形状"。**多一张卡换掉整个模板化风险**

张数:**镇级 2 张 + 建筑级 1 张 = 3 张**。要压缩就砍建筑级那张,
**镇级两张是挡法本身,不减到一张**。

#### 复评修订 A(2026-08-04):格式落在 `diagram-conventions-zh.md` §六,顺手还一笔债

原计划没写格式规范**落在哪个文件**,三条 checkbox 全部悬空。定为该文件新增一节,四条理由:

   `git log -S"文字地图卡" --all` 为空,**这是一处从未被定义过的悬空术语**。
   它与 P5 阶段 0 还的那笔债是同一类 bug,只是降了一级:那次是显式路径(grep 得到、
   索引脚本查得出),这次是一个**裸名词**(两者都看不见,当时 `--check` 照样报 no problems)。
   成因是 P5 阶段 3(未做)那条 checkbox「只出 mermaid 与文字地图卡」的内容,被提前抄进了
   §四。**本计划阶段 2 就是它的定义,写进同一个文件即当场还清。**
2. **分类正确。** 按 `craft/README.md`,地图卡是**惯例规范**(kit 自订画法),

3. **同一批消费方。** §四 区域关系图的读者就是 `core/03` 的 town/region 路径。
4. **省一份维护。** 新文件 3 → 2:少一处 `core/03` 接线、少一份 README 条目、少一个索引对象;

收尾时**必须同步改 §四 第 69 行**,把裸名词改成指向 §六 的显式引用。

#### 复评修订 B(2026-08-04):建筑级那张卡与现有惯例直接冲突,必须同时改 §五

`diagram-conventions-zh.md` 有两处写死**建筑内部布局不归它管**:第 10 行
