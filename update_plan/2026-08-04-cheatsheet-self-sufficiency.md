## 目标

**让 `reference/rules/` 单独就能回答规则问题,然后把规则书从版本库里请出去。**

今天查一条战斗规则的代价是:`core/02` 说速查表说不清就回 `keeper-rulebook-7e-zh.md`
查原文 → 那份文件没有任何可跳读的标题结构(全文只有两个 `##`),只能 grep 定位再
大段硬读 → 一次查询几万 token。速查表越薄,回落到硬读的次数就越多。

所以这不是两件事,是一件事的两半:**速查表必须先补到能自足,规则书才退得掉。**

### 转录稿的噪声(影响"一字不落"怎么落地)

规则书是 PDF 文字提取的产物,正文里混着三类不该进速查表的东西:

1. **页眉页脚**——「克苏鲁的呼唤 第七版」「第六章 战斗」成行插在句子中间,
   甚至把一句话切成两半(如 3401:「比起精确地让时间在战斗轮中实时流克苏鲁的呼唤 第七版」)
2. **洛氏小说引文**——每节开头一段(如 6.2 开头引《墙中之鼠》)
3. **哈维·沃尔特的逐轮范例**——占第六章相当篇幅,是教学材料不是规则

**"一字不落"要落到规则条文上,不是落到这三类噪声上。** 体例见「方案」。

## 风险与边界

1. **膨胀失控。** "一字不落"没有天然刹车。bundle 退役后**体积不再是硬约束**,但
   "速查表"三个字仍然是——一份 1,500 行的 `combat.md` 在牌桌上翻不动。挡法是阶段 0 的
   样例先量膨胀比,以及体例第 5 条(不收页眉、引文、教学范例)。**样例算出来若三份合计
   超过 2,000 行,先回来议要不要按小节拆文件**(拆文件 ≠ 分两层,拆完每份仍然完整)。
2. **转录稿本身不可靠。** 规则书头部自述「部分章节尚未系统校对」,且是 PDF 提取产物。
   本计划是把它当唯一依据来重写速查表——**遇到明显断字、错行、数值可疑处,标
   `<!-- 待核 -->` 而不是猜**。退役后这些标记就是欠账清单,不许静默填平。
3. **和 P11 年代包的耦合。** `eras/*.md` 是对 `character-creation.md` 的差集。阶段 2 动那份
   基准本时,六份年代文件的 delta 可能失效——**阶段 2 动它之前先扫一遍 `eras/`**。
4. **这次改的是"最后一句话"归属。** 现在的链条是「速查表 → 说不清 → 规则书」。改完
   速查表就是终点。**代价是速查表错了没人兜底**——而「根因」一节已经证明没人兜底会
   出什么事(四份错表全部诞生于手上没有原文的时期)。所以阶段 1.3 的三条抽查不是形式,
   以后每次改速查表都该照做。
5. **和 P13(bundle 退役)的关系:无硬依赖,但别在同一个 commit 里做。** 两边都要动
   `reference/README.md`、`core/00`、三份适配器,同批改会把两件事的理由搅在一起,
   以后 `git log` 读不出「规则条文可转录」是为了什么改的。
6. **不做的事**:`grand-grimoire-zh.md`、`malleus-monstrorum-zh.md` 两份**不动**。
   它们是条目型资料(法术、怪物),按条查、不需要通读,没有规则书那种"无结构硬读"的病;
   而且 `monster-index.md` 已经是它对外的通道。Keeper 只点名了规则书。

## 备忘:为什么规则书**留在 `sourcebooks/`**,既不 gitignore 也不移进 `reference/_source/`

这一节原本记的是"原地留档 + gitignore"(已定案 ②)相对"移进 `_source/`"的取舍。
**2026-08-04 晚 Keeper 撤回 gitignore 那半边之后,两个候选方案都不成立了**,结论反而更简单:
**`keeper-rulebook-7e-zh.md` 就是一份普通的入库归档件,原地不动。**

- **不 gitignore**:「可以 gitignore pdf,但是 md 一定要有」。同名 `.pdf`(14.8 MB)
  由现有 `*.pdf` 规则挡着,这本来就够了。
- **不移进 `_source/`**:`_source/` 是**料场**,放的是还没走 `core/14` 归档流程的原始素材;
  规则书早在 39d1625 就走完流程进了 `sourcebooks/`,有头部块也有 `## 引用出处`,
  往回搬是降级,而且会白白打断 8 处引用之外的路径。
  (`_source/` 自 2026-08-04 起也不再是"永不入库"的目录了,见 `reference/_source/README.md`
  ——所以"搬去 `_source/` 就等于出库"这个前提本身也已经不成立。)
- **保留的那条代价没变**:模型仍会在 `reference/sourcebooks/` 里看见它,仍可能硬读。
  **所以阶段 1.2 改掉那 8 处引用是必做项,不是收尾项**——现在它更是 1.2 的**全部内容**,
  因为再没有"出了版本库就读不到"这层被动兜底了。
