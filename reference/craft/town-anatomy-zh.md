# 城镇解剖手法稿 — 简体中文

从 `reference/_source/arkham-zh.md`(阿卡姆城市资料,9 段区导言 + 门牌编号法则 + 反查
名录,2026-08-04 采料后蒸馏)提炼出的**技法**笔记,供 `core/03-build-world.md` 的
town/locale 路径使用。

**这不是文摘,是技法字典。** 只记录"一个 1920s 新英格兰镇怎么被搭出来",不重制阿卡姆
写了什么——依 `core/00-how-to-run.md` 的三分法,已出版虚构内容取手法永不取文字。**下面
不出现任何阿卡姆的具名街道、机构或人物**,举例一律原创;引用源材料时只标条目编号,
供追溯核对,不是内容本身。

## 一、城镇部件清单 — 一个区靠四个维度立住

每一区(或一个小镇整体)至少要回答四个问题,答案决定这一区该塞进哪些地点、住着哪种
NPC。这四维是从阿卡姆九个区的导言段里通读出的公约数,不是凭空设计的清单:

| 维度 | 在问什么 | 常见答案的形状 |
|---|---|---|
| 地势 | 河边/坡地/洼地,直接决定谁负担得起哪块地 | 河谷向上坡地(老钱在高处)/ 两山之间的低洼沼泽(全镇最穷的人住这) |
| 建筑年代与样式 | 老钱区总比新区先盖,样式混搭看得出财富怎么流动 | 殖民地/乔治王朝式老宅与拥挤木屋并存于同一条主街两端 |
| 族裔与阶层 | 谁住哪、彼此怎么分层——阶层常按地势垂直分布 | 山顶体面家族、山腰新移民、山脚最贫困的一批同山不同层 |
| 经济角色 | 这一区替全镇干什么活 | 金融与专业办公区 / 旧贸易与移民店铺带 / 学术飞地 / 半废弃工业带 |

**九个区没有两组答案是重复的。** 这是本节唯一要守住的纪律:别把镇写成"住宅区/商业区"
两分法,每一区都该有一句独属于它的身份——地势变了,阶层跟着变,经济角色也该跟着变,
三者互相咬合,不是各填各的。

## 二、地点条目的字段体例

单条地点固定这个骨架:

```
<三位或四位编码>          ← 首位数字 = 区号,后两位 = 区内序号;不按街道顺序排列
<地点名>
<街道地址(门牌号)>
<散文描述:功能 / 营业时间或作息 / 一个硬数字(租金、价格、费用)/ 一条可深挖的钩子>
<可选:住客或雇员的独立段落>  ← 有姓名、有一两句行为模式,视密度需要给数值或"重要技能"
```

**门牌编号法则**(与具体镇名完全解耦,任何镇都能照搬):编号原点定在两条主街的交汇处,
四个方向各自从 100 起升序;跨多个路口的大街区按四个街区计数;沿升序方向前进时偶数在
右、奇数在左;只出现在镇的四分之一区域的街道不带方向前缀。**街道拐弯、加建、院内地址
会让编号读起来不连贯——这是特性不是 bug**,巷弄一律不必标进地图,留给 KP 现场发挥。

**反查索引层。** 名录之外再挂一张"按用途反查"的表(教堂 / 旅馆公寓 / 医疗机构……),
让 KP 现场找"哪里能看病、哪里有教堂"时不必翻遍整个区。这本身是一条独立可复用的手法,
不依赖具体镇的内容——`reference/tables/town-institutions.md` 就是这层索引的原创抽象版。

## 三、神话层怎么混进世俗名录

阿卡姆的做法**不是**给神话内容单开一个分区或加星号标记。禁书、诅咒之物这类料,分散挂
在私宅书房、大学或公共图书馆、旧书店、公寓房客的私人收藏、神秘学社团总部这些**完全世俗
的地点类型**上,和五金店、律所同一张表里并排,反查索引也不给它们单独归类。

**这是一条可执行的写法约束,不是态度。** 建镇时,与其列一份"这个镇的神话清单",不如
先把 `town-institutions.md` 掷出的世俗地点清单填满,再回头挑一两个**貌似无关的普通条目**
(私人藏书家、旧书商、某个体面社团)把神话层缝进去,不新增条目、不加标记。裂缝要在
KP 备课时心里有数,不能在玩家能读到的名录格式上露出来。

## 四、地点的三档密度

同一张名录里,条目长度不是均匀的,观察到三档,混排、不强求等长:

- **一句话设施** —— 纯功能描述,四行以内,没有钩子也没有人。约占样本的六分之一。
- **带钩子的场所** —— 功能描述之外多一句可深挖的细节(一桩旧案、一条隐藏的服务、一个
  怪癖的机制),但没有独立的人物段落。样本中占比过半,是最常见的一档。
  条目本身也可能**就是**一个人——地址只是这个人的门牌,没有另起段落。
  (参照阿卡姆 101/102/105/110/115/119/124 等条目观察所得)
- **带独立子条目的场所** —— 挂着一段有名字的独立内容(一个房客、一个雇员、有时是一个
  团体而非个人),视重要性给"重要技能"一行或一整套数值。样本中不到三分之一,是密度
  最高的一档,通常也是这一区 NPC 的落点。(参照阿卡姆 108/112/113/116/118 等条目观察所得)

**NPC 不是均匀撒在名录里的,是挂在少数地点上。** 建镇时先决定"这一区哪几条会是第三档"
(通常 1–2 条,呼应本套件既有的 3–5 个 notable NPC 原则),其余条目留在前两档,不必每
条都配人。

## 使用方式

- `core/03-build-world.md` 建 town/locale 时:§一 定区的身份、§二 定地点条目怎么写、
  §三 决定神话层怎么埋、§四 决定这一区的 NPC 落在哪几条。
- 门牌法则(§二)与地点密度(§四)是通用手法,任何年代/地域的城镇都能套;§一 的四维
  同样通用,具体答案随战役的年代与地域重写。
- 具体地点内容仍按 `reference/tables/locations.md`(舞台)与
  `reference/tables/town-institutions.md`(机构清单)掷骰产生,本文件只管"怎么写",
  不提供任何一个可以直接搬用的地点。
